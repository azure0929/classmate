비로그인 사용자는 공개 강의 정보와 무료 외부 학습 자료를 둘러볼 수 있습니다. 시청, 라이브 참가, 찜처럼 계정 상태를 바꾸거나 상호작용을 남기는 동작은 로그인 후 이용하도록 구분했습니다. 읽기 전용 공개 Q&A는 강의 시청 화면의 일부이므로 시청 권한을 따릅니다.

## 구현 경계와 이슈 해결

- **비로그인 직접 URL 접근:** 상세 페이지의 시청 CTA뿐 아니라 `/courses/{courseId}/watch` 직접 진입도 확인합니다. 로그인하지 않았다면 안내와 로그인 창을 표시하고, 시청 화면의 소켓 연결은 시작하지 않습니다.
- **화면 간 세션 불일치:** 페이지마다 독립적으로 데모 세션을 만들면 헤더와 시청 화면의 로그인 상태가 달라질 수 있어 웹/관리자 앱 각각의 루트에서 공통 `DemoSessionProvider`를 사용합니다.
- **역할별 화면 접근:** 데모 로그인에서 학습자·강사·관리자 역할을 선택할 수 있습니다. 강사/관리자 워크스페이스는 강사 또는 관리자만 표시합니다.
- **Q&A 소유권:** 브라우저가 보낸 작성자 이름만 믿지 않도록 서버가 연결 ID를 기록합니다. 수정·삭제 이벤트는 연결 ID, 강의 Q&A 룸 참가 여부, 글자 수를 서버에서 확인하고, 변경 사항은 해당 강의 참가자에게 브로드캐스트합니다.
- **공개 영상의 저작권과 출처:** 영상 파일을 복사하거나 내려받지 않고 원본 YouTube 영상의 임베드와 채널 링크를 사용합니다. 19개 영상 ID의 제목·채널은 YouTube oEmbed 응답으로 확인했습니다. 임베드 허용 여부 및 영상 생존 여부는 크리에이터가 바꿀 수 있습니다.
- **결제 범위:** 이전 요구대로 결제·장바구니는 만들지 않았습니다. 실제 구매 기능인 것처럼 보이는 버튼도 추가하지 않았습니다.

## 포트폴리오 데모와 운영 서비스의 차이

역할 선택은 브라우저 저장소에 기록되는 데모 상태이지 계정 인증이 아닙니다. 따라서 역할을 선택해 우회할 수 있으며 서버/API 인가를 대체하지 않습니다. 실제 서비스에서는 신뢰 가능한 서버 세션과 역할·강의 등록 권한 검증이 필요합니다.

현재 채팅/Q&A 저장소는 시그널링 서버 메모리이며 최근 100개만 유지합니다. 작성자 소유권이 Socket.IO 연결 ID에 묶여 있어 재접속하면 이전 글을 수정할 수 없습니다. 운영 전환 시 영속 사용자 ID와 데이터베이스, 연결된 계정 권한 검사, 요청 빈도 제한을 추가해야 합니다.

강의 데이터와 강의 자체 VOD는 모의 데이터/데모 플레이어입니다. `/resources`의 공개 영상은 실제 공개 영상 재생이지만 별도의 학습 상품이나 해당 모의 강의의 전체 커리큘럼 영상은 아닙니다. 실제 코스 VOD·진도율·완료 이력·인증서·결제·환불·강사 정산·다국어 및 React Native 앱은 범위를 가장한 화면만 추가하지 않고, API와 정책이 정해진 뒤 별도 설계해야 할 영역으로 남겼습니다.

## 검증 체크리스트

1. 로그아웃 후 강의 검색·상세·무료 영상은 열리고, 강의 시청 CTA와 라이브 입장은 로그인 안내를 표시한다.
2. 로그인 성공 시 원래 요청한 강의 시청 화면으로 이동한다.
3. 학습자 역할로 `/admin`에 접근하면 운영 데이터가 보이지 않으며, 강사/관리자 역할은 대시보드에 접근할 수 있다.
4. Q&A 작성자는 수정/삭제 버튼을 볼 수 있고, 다른 연결은 해당 버튼을 볼 수 없다. 다른 소켓이 위조 이벤트를 보내도 서버 데이터는 변경되지 않는다.
5. 좁은 화면과 긴 스크롤에서도 상단 계정 조작부가 보이고, 헤더가 본문을 가리지 않는다.
